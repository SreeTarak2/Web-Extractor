IMAGE EXTRACTION (PRIORITY ORDER — ALWAYS FOLLOW THIS)
==================================================
You MUST populate image.primary.url. Follow these steps in order:

STEP 1 — Check PRE-EXTRACTED IMAGE DATA in the message:
  - If banner_url is NOT "(none)", use it as primary.url
  - Else if logo_url is NOT "(none)", use it as primary.url

STEP 2 — If Step 1 yielded nothing, search the raw scraped data for these fields:
  "image", "image_url", "img", "img_url", "thumbnail", "picture",
  "cover_image", "banner", "photo", "media"
  Use the FIRST valid http(s) URL found.

STEP 3 — If still not found, scan the HTML content for the first
  prominent <img src="..."> or og:image that is clearly related
  to this contest (not a logo, ad, or nav icon).

STEP 4 — Only set primary.url = null if truly NO image exists in any source.

image.alt:

  - Else derive from the contest title (short descriptive phrase)

==================================================
FEE INFERENCE RULES (DECISIVE — DO NOT DEFAULT TO NULL)
==================================================
Determine isFree from these signals:

isFree = true:
  - Contest explicitly states "free", "no entry fee", "no fee", "$0 entry"
  - No mention of any payment anywhere

isFree = false:
  - Any fee amount is mentioned (£8, $10, "per entry")
  - Fee is described as "Unknown" or "TBD" (a fee exists, amount unknown)
  - Early bird discount is mentioned (implies a paid entry)
  - "Registration fee", "submission fee", "entry fee" appears

isFree = null:
  - Only if fee is COMPLETELY unmentioned in all sources

When isFree = false and amount is known: fill amount + currency
When isFree = false and amount is unknown: amount = 0, currency = "N/A"
When isFree = true: amount = 0, currency = "N/A"

==================================================
PRIZE RULES (EVIDENCE-BASED)
==================================================
originalAmount: the raw number from source (in stated currency)
totalUSD: USD equivalent (convert if currency is known; else same as originalAmount)
currency: ISO code e.g. "USD", "EUR", "GBP", "INR" — default "USD" if not stated

Classification:
1. Explicit amount → isMonetary = true, fill originalAmount + totalUSD
2. Monetary mentioned, no amount → isMonetary = true, both amounts = 0
3. Only non-monetary (certificates, recognition, publication) → isMonetary = false
4. No prize info at all → isMonetary = null, both amounts = 0

Prize extraction hints:
- Check the contest title for prize amounts (e.g., "up to $10,000")
- Check description for prize breakdowns (1st: £1000, 2nd: £500…)
- For multiple prizes, use the total sum as originalAmount
- For "up to X" prizes, use X as originalAmount with isMonetary = true

description: summarize the prize in plain text (e.g., "Cash prizes totalling £1,950 across four categories")

==================================================
DEADLINE EXTRACTION RULES
==================================================
The raw scraped data represents a SINGLE, pre-identified contest.

PRIMARY RULE — Structured fields (use directly, no ambiguity check needed):
  If the raw data contains any of these fields with a date value, extract it:
  "deadline", "date", "end_date", "submission_deadline", "closes",
  "due_date", "expiry", "cutoff", "closing_date"
  → Use as submissionDeadlineUTC.

  If the raw data title or description contains a parenthetical deadline like
  "[ X days remaining ]" with an accompanying date, use that date.

SECONDARY RULE — HTML text (apply ambiguity check):
  When parsing raw HTML for a date, ensure the date is unambiguously for THIS
  contest and not a list of other contests' dates.

  VALID from HTML:
  - "Deadline: March 1, 2026" directly tied to this contest's section
  - "Submit by April 24, 2026" in the contest's own description block

  INVALID from HTML:
  - A table listing many contests with many different dates
  - A page-level sidebar showing upcoming deadlines for multiple events

  If HTML date is ambiguous → fall back to null for that field only.
